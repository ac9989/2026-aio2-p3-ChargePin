# API 연결 점검
점검일: 2026-11-05. Frontend 외 파일은 수정하지 않음. 외부 API 추가 호출 및 브라우저 시연 없이 코드·컨테이너 설정·내부 health 연결을 점검함.

## 연결 구조
| 기능 | 경로 | 현재 근거 / 한계 |
| --- | --- | --- |
| 지도 | 브라우저 → Kakao Maps JavaScript SDK | 프론트 JS 키 설정 확인. 로딩 결과는 지도 내부에서 표시하며 대시보드에 SDK 성공 이벤트는 전달하지 않음 |
| 장소 탐색 | Frontend → backend:8000/api/v1/places/suggest → Kakao Local keyword | REST 키 설정 확인. 두 글자 이상 입력 시 호출. 빈 결과도 정상 응답으로 기록 |
| 채팅 계획 | Frontend → /api/v1/chat/plan → 규칙 Planner → Executor → Kakao Local | 후보 또는 search_request가 반환되면 장소 조회 응답을 받은 근거로 기록. NEEDS_INPUT만으로 원천 성공·실패 단정 불가 |
| 충전소 | /api/v1/search 또는 /search/{id}/confirm → Executor → KECO getChargerInfo/getChargerStatus → Critic | 서비스 키 설정 확인. HTTP 성공과 원천 정상·최신성은 별개. degraded 응답 가능 |
| 백엔드 health | Frontend 컨테이너 → http://backend:8000/healthz | 점검 시 ok 응답. 외부 API 상태·DB·캐시 전체 health를 의미하지 않음 |
| 캐시 | 백엔드 메모리 캐시 | 정보 600초, 상태 30초 기본값. 프론트에서 hit·갱신·실패 지표 관측 불가 |
| LLM | 현재 없음 | 현재 Planner는 규칙 기반. 별도 LLM API 호출 없음 |
| 서울시 주차 API | 현재 없음 | 현재 충전소 조회 경로는 KECO이며 주차 무료·제한 문구는 KECO 부가정보 |
| 배포·감사·시계열·품질 집계 | 현재 없음 | 운영 대시보드용 별도 집계 API 미구현 |

## 표시 오류 수정
이전 카카오 장소 라벨은 현재 후보 리스트/선택 상태만 참조하여 챗에서 조회해도 이력 없음으로 표시될 수 있었음.
현재는 프론트가 관측한 요청 메서드·경로·결과·시각·왕복 시간을 세션 내 최근 100건까지 보관함.
토큰·키·검색 원문·API 응답 본문은 보관하지 않음.
후보가 0개인 정상 응답도 호출로 기록하고, 장소 조회 실패와 구분함.
챗의 장소 조회는 후보/검색 조건이 반환된 경우만 근거로 삼음.
프론트 왕복 시간은 백엔드 처리를 포함하며 카카오 자체 응답 시간으로 해석하지 않음.
기존 세션의 과거 요청 이력은 복원할 수 없음. 새 요청부터 기록함.

## 배포 불일치
실행 중 backend의 app/agents.py와 로컬 Backend/app/agents.py의 SHA256이 다름.
- 실행 중 이미지: 챗 반경 기본 3km, 명시된 1/3/5km 일부 해석, 모호한 후보 확정은 3km.
- 로컬 코드: 챗 기본·확정 반경 0.5km로 변경된 버전.
- 두 버전 모두 장소 인식이 서울역·시청·강남역 등 규칙 중심으로 제한됨.
- 백엔드 재빌드는 이번 점검에서 수행하지 않았음.
- 프론트는 0.5km 안내 문구와 실행 중 서버 반경이 불일치할 수 있으므로 별도 반영 필요.
