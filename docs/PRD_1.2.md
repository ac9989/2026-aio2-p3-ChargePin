# ChargePin PRD 1.2

> **묻는 대로, 확인된 만큼.** 서울 전기차 충전소를 자연어와 지도에서 찾고, 확인된 상태 정보만 안내하는 멀티 에이전트 서비스

- 문서 버전: 1.2
- 작성일: 2026-11-09
- 기준: `main`의 FastAPI·Streamlit·Docker Compose·GitHub Actions 구현
- 1.1 대비 반영: 구조화 운영 로그 영속, Discord 실패 알림, PostgreSQL 운영 이력 및 파일 로그 이중 저장

## 1. 제품 정의

| 항목 | 내용 |
| --- | --- |
| 서비스명 | ChargePin |
| 사용자 문제 | 운전자는 가까운 충전소의 위치·충전기 상태·보고 시각을 함께 확인하기 어렵다. 장소 정보와 충전 상태의 출처도 서로 다르다. |
| 해결 방식 | 카카오에서 서울 내 장소 후보·지도를 받고, 환경공단(KECO)에서 충전기 상태·보고 시각을 조회한다. 불확실한 정보는 추정하지 않고 `정보 지연` 또는 `확인 불가`로 표시한다. |
| 핵심 사용자 | 서울에서 전기차 충전소를 찾는 운전자와 검색·장애 상태를 확인하는 운영자 |
| 제품 범위 | 전기차 충전소 탐색이 중심이다. 일반 주차장 탐색·빈자리 예측은 이번 범위에 포함하지 않는다. |

## 2. 목표와 완료 기준

1. 지도·사이드바·자연어로 서울 내 충전소를 찾는다.
2. 장소 후보와 충전기 상태의 출처·갱신 시각을 분리해 표시한다.
3. 위험 입력, 오류, 재시도, Critic 판정을 추적하되 원문·키·토큰은 남기지 않는다.
4. 테스트가 통과해야 이미지 빌드·배포가 진행되며, 실패 시 팀 Discord 채널에 알린다.

| 구분 | 완료 기준 |
| --- | --- |
| 검색 | 서울 내 카카오 후보를 선택한 뒤 표시 범위 1·2·3 km와 급속·완속 조건으로 결과를 표시한다. |
| 신뢰성 | 결과마다 출처·최종 보고 시각을 표시하고 지연·이상 데이터는 안전한 상태로 바꾼다. |
| 자연어 | 명확한 장소·수치는 규칙으로 빠르게 처리하고 문맥형 조건 변경만 LLM으로 해석한다. |
| 추적 | `request_id`로 Handoff·재시도·Critic 판정을 연결하고, 안전한 운영 이벤트를 PostgreSQL과 파일 로그에 남긴다. |
| 배포 | CI 실패 시 다음 빌드·게시 단계가 차단되고 Discord 웹훅 알림을 보낸다. |

## 3. 사용자·역할

모든 사용자는 같은 메인 화면을 본다. 역할에 따라 버튼 동작만 다르며, 서비스 키·외부 API 키 원문은 화면·응답·Handoff·로그에 노출하지 않는다.

| 역할 | 가능한 일 | 제한 |
| --- | --- | --- |
| 손님(GUEST) | 지도·사이드바 검색, AI 채팅, 결과 조회 | 운영 대시보드 버튼을 누르면 블러와 `관리자 전용 화면입니다.` 팝업을 표시한다. |
| 하급 관리자(JUNIOR_ADMIN) | 손님 기능, 운영 대시보드 조회, 요청 재처리·캐시 갱신 | Test API 장애 주입과 상급 전용 보고서 내보내기는 할 수 없다. |
| 상급 관리자(SENIOR_ADMIN) | 하급 관리자 기능, 시연 모드 Test API 제어, 운영 보고서 내보내기 | 역할 변경과 키 원문 조회는 할 수 없다. |

## 4. 핵심 사용자 흐름

### 4.1 첫 진입·사이드바

1. 첫 진입 시 강남역 주변 표시 범위 1 km(실제 반경 0.5 km), 급속·완속으로 기본 검색한다.
2. 사이드바 `검색 중심`은 빈 상태로 시작하며, 장소명을 입력하면 카카오 연관 후보를 표시한다.
3. 사용자가 서울 내 후보 하나를 선택하면 좌표를 검색 중심으로 확정하고 충전소 검색을 실행한다.
4. 지도 hover에는 상호명·현재 빈자리/총 충전기 수를, click에는 상태·출처·보고 시각·상세 정보를 보여 준다.

### 4.2 자연어 채팅

1. 입력 가드레일이 지침 무시·비밀 정보·타인 정보·권한 변경 요청을 먼저 차단한다.
2. `사당역`, `서울역 2km 급속`처럼 명확한 입력은 규칙 기반 Planner가 SearchRequest 초안을 만든다.
3. `그 조건에서 급속만`, `두 키로 정도로 바꿔줘`처럼 문맥·한국어 수량 해석이 필요한 입력만 GPT-4o mini를 사용한다.
4. `서울`, `강남` 같은 넓은 장소는 카카오 후보 상위 2개와 1순위 제안을 보여 준다.
5. 사용자가 장소·조건을 확인한 뒤에만 환경공단 충전기 상태 조회를 시작한다.
6. 표시 범위 1·2·3 km 밖의 요청은 검색하지 않고 지원 범위를 안내한다.

| 검색 조건 | 규칙 |
| --- | --- |
| 지역 | 서울 주소의 카카오 장소 후보만 선택하며 서울 밖 후보·충전소는 제외한다. |
| 타입 | 급속, 완속, 급속·완속 전체 |
| 화면 표시 범위 | 1 km, 2 km, 3 km |
| 실제 API 반경 | 각각 0.5 km, 1.0 km, 1.5 km |

## 5. 기능 요구사항

### 5.1 검색·품질

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| FR-01 | 카카오 장소 API와 JavaScript SDK를 사용한다. | 카카오는 장소 후보·좌표·지도에만 쓰며 충전 가능 상태의 근거로 쓰지 않는다. |
| FR-02 | 환경공단 API로 충전기 상태·보고 시각을 조회·정규화한다. | 출처·최종 보고 시각이 결과에 함께 표시된다. |
| FR-03 | 사이드바 검색은 Planner를 거치지 않는다. | 선택된 후보로 만든 동일 SearchRequest가 Executor·Critic·Memory Keeper 경로로 합류한다. |
| FR-04 | 채팅 검색은 사용자 확인 후 상태를 조회한다. | 후보·조건 확인 전에는 환경공단 충전기 조회를 실행하지 않는다. 첫 진입 기본 검색은 예외다. |
| FR-05 | 오래되거나 비정상인 데이터는 안전하게 표시한다. | 보고 시각이 7일 초과·누락이거나 빈자리 수가 음수/전체 초과이면 `정보 지연` 또는 `확인 불가`로 표시한다. |
| FR-06 | 실패 원인을 사용자에게 안전하게 안내한다. | 결과 없음, 429, 인증 만료, API 지연, LLM 실패는 안전한 원인 범주만 표시하며 내부 예외는 노출하지 않는다. |

### 5.2 멀티 에이전트·가드레일

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| FR-07 | Planner·Executor·Critic·Memory Keeper는 책임과 권한이 겹치지 않는다. | Planner/Critic은 제공처 API를 호출하지 않고, Executor만 허용된 제공처를 호출한다. |
| FR-08 | 모든 검색 단계는 `request_id`로 연결한다. | SearchRequest·출처·보고 시각·재시도·Critic 판정이 Handoff에 연결된다. |
| FR-09 | 위험한 채팅 입력은 Planner·Provider보다 먼저 차단한다. | 차단된 입력이 도구 호출에 도달하지 않으며 원문은 Handoff·로그에 저장하지 않는다. |
| FR-10 | 확인하지 못한 충전 상태를 단정하지 않는다. | Critic이 `PASS` 또는 `SAFE_UNAVAILABLE`로 결과 품질을 판정한다. |

### 5.3 운영·로그·알림

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| FR-11 | 운영 대시보드는 요청·가드레일·재시도·품질·힐링·이력 저장소 상태를 표시한다. | PostgreSQL 누적 이력과 `logs/service.log` 감사 이력을 구분해 관리자에게 제공한다. |
| FR-12 | 운영 이벤트를 이중 저장한다. | `operation_events`와 `logs/service.log`에 Handoff 전이, 감사, 결과 요약, 재시도, 가드레일, 오류의 안전한 메타데이터를 기록한다. |
| FR-13 | 오류 로그를 분리한다. | 오류 수준 이벤트만 `logs/errors.log`에 기록한다. 로그 실패가 검색 요청을 중단시키지 않는다. |
| FR-14 | 로그에 비밀·원문을 남기지 않는다. | 채팅 원문, API/서비스 키, Bearer 토큰, 제공처 원문 응답을 기록하지 않는다. |
| FR-15 | CI·CD 실패를 팀 채널에 알린다. | `ALERT_WEBHOOK_URL` Secret이 설정된 경우 실패한 CI 또는 CD 실행 링크를 Discord 웹훅으로 전송한다. Secret 미설정 시 알림만 건너뛴다. |
| FR-16 | 운영자는 실패 요청을 수동 재처리하고 캐시를 갱신할 수 있다. | 관리자 요청 재처리는 요청당 최대 2회이며, 횟수·사유가 안전한 운영 이벤트로 남는다. |
| FR-17 | DB 연결 오류가 검색을 멈추지 않는다. | DB 쓰기·읽기 실패 시 DB 상태만 `연결 대기`로 낮추고 파일 로그·현재 메모리 폴백을 계속 사용한다. |

## 6. 데이터·보안 정책

| 데이터 | 보관 위치·목적 | 제한 |
| --- | --- | --- |
| 장소 후보·좌표·지도 | 카카오 API/SDK, 장소 해석·지도 표시 | 충전 상태 근거로 사용 금지 |
| 충전기 상태·보고 시각 | 환경공단 API, 충전 상태 판정 | 지연·누락·이상값은 Critic이 안전 처리 |
| SearchRequest·Handoff·대화 문맥 | 백엔드 프로세스 메모리 | 컨테이너 재기동 시 초기화, 채팅 원문은 운영 로그에 쓰지 않음 |
| 운영 이벤트 | PostgreSQL `operation_events`, `logs/service.log`, `logs/errors.log` | 안전한 이벤트만 DB·파일에 이중 저장, DB 장애 시 파일 로그 폴백, Git에는 올리지 않음 |
| 자연어 구조화 | OpenAI GPT-4o mini | 문맥형 조건 해석만 수행하며 제공처 도구·시크릿에 접근하지 않음 |
| Discord 웹훅 URL | GitHub Actions Secret `ALERT_WEBHOOK_URL` | 코드·`.env`·로그·화면에 원문을 남기지 않음 |

## 7. 비기능·배포 요구사항

| 영역 | 기준 |
| --- | --- |
| 응답 속도 | 명확한 장소·숫자는 규칙 빠른 경로를 우선하며 LLM은 필요한 문맥형 요청에만 호출한다. |
| 장애 격리 | 재시도 가능한 Provider 오류와 일시적 Executor·Planner 구조화 오류는 0.25초·0.5초 간격으로 자동 최대 2회 재시도한다. 인증 오류·지속 오류는 안전한 종료로 전환한다. |
| 기록 보존 | Handoff·세션은 메모리지만 안전한 운영 이벤트는 Compose PostgreSQL과 호스트 `logs` 볼륨에 남는다. |
| 키 관리 | 시크릿은 `.env` 또는 GitHub Secret으로 주입하고 브라우저에는 지도 JavaScript 키만 전달한다. |
| 테스트 | Backend 48개, Frontend 24개, Ops 13개 테스트를 CI 게이트로 사용한다. |
| 배포 | `pytest` → Compose 검증·이미지 빌드 → GHCR 게시(main) → AWS EC2 Docker Compose 배포·healthcheck → 실패 시 이전 SHA 롤백을 시도한다. |
| 실패 알림 | CI/CD에서 실패한 경우 Discord 웹훅 알림을 보내며, 알림 Secret 미설정 자체는 배포 실패로 처리하지 않는다. |

## 9. 범위 제외

- Kubernetes Pod·Service·매니페스트 운영
- Redis 같은 별도 캐시 DB와 DB 연결 오류의 반복 장애시험
- 일반 주차장 탐색, 실시간 주차 빈자리, 빈자리 예측
- 충전·주차 요금과 외부인 이용 가능 여부의 확정 표시
- 역할 승급·강등 관리 화면
- 실제 API 키·세션 토큰·개인정보의 화면·응답·Handoff·로그 표시

## 10. 승인 체크리스트

- [ ] 지도·사이드바·자연어 채팅이 SearchRequest 계약에 따라 동작한다.
- [ ] 카카오 장소와 환경공단 충전 상태의 역할·출처·시각이 분리되어 표시된다.
- [ ] 입력·행동·출력 가드레일과 Handoff 이력이 구현된다.
- [ ] 자동 재시도 최대 2회와 안전한 실패 응답이 동작한다.
- [ ] `logs/service.log`·`logs/errors.log`가 원문·키·토큰 없이 구조화 이벤트를 남긴다.
- [ ] 테스트 실패 시 다음 CI 단계가 차단되고 Discord 알림이 도착한다.
- [ ] Docker Compose 실행과 GitHub Actions 배포 게이트를 확인한다.
