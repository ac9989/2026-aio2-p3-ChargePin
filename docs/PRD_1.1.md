# ChargePin PRD 1.1

> **묻는 대로, 확인된 만큼.** 서울 전기차 충전소를 자연어와 지도에서 찾고, 확인된 상태 정보만 안내하는 멀티 에이전트 서비스

- 문서 버전: 1.1
- 작성일: 2026-11-09
- 대상: ChargePin P3 구현·시연 기준

## 1. 제품 정의

| 항목 | 내용 |
| --- | --- |
| 서비스명 | ChargePin |
| 사용자 문제 | 운전 중 사용자는 가까운 충전소의 위치와 이용 가능 여부를 빠르게 판단하기 어렵다. 지도 장소 정보와 충전기 상태 정보의 출처·갱신 시각도 서로 다르다. |
| 해결 방식 | 카카오에서 서울 내 장소 후보와 지도를 제공하고, 환경공단(KECO)에서 충전기 상태를 조회해 한 화면에 표시한다. 불확실한 정보는 추정하지 않고 `정보 지연` 또는 `확인 불가`로 표시한다. |
| 핵심 사용자 | 서울에서 전기차 충전소를 찾는 일반 운전자, 서비스 상태를 확인·재처리하는 운영자 |
| 제품 범위 | **전기차 충전소 탐색이 중심**이다. 일반 주차장 탐색, 주차 빈자리 예측은 이번 범위에 포함하지 않는다. |

## 2. 목표와 성공 기준

### 2.1 제품 목표

1. 사용자가 지도·사이드바 또는 자연어로 서울 내 충전소를 찾는다.
2. 장소 후보, 충전기 상태, 출처와 갱신 시각을 구분해 잘못된 확신을 주지 않는다.
3. 입력 가드레일, 역할별 화면 제어, 재시도·복구 이력을 운영 대시보드에서 확인한다.
4. 테스트를 먼저 통과한 변경만 컨테이너 이미지 빌드·배포 단계로 진행한다.

### 2.2 완료 판단

| 구분 | 완료 기준 |
| --- | --- |
| 검색 | 서울 내 장소 후보 선택 후 1·2·3 km 검색 범위와 급속·완속 조건으로 충전소 결과를 표시한다. |
| 신뢰성 | 각 결과에 출처·최종 보고 시각을 표시하고, 지연·이상 데이터는 안전한 상태로 바꾼다. |
| 자연어 | 명확한 장소는 빠르게 처리하고, 문맥형 조건 변경만 LLM으로 해석한다. |
| 보안 | 지침 무시·비밀값 요청·타인 정보·권한 변경 요청은 Provider 호출 전에 차단한다. |
| 운영 | 자동 재시도 최대 2회, 수동 재처리·캐시 갱신, Auto Healing·배포 이력을 대시보드에 표시한다. |
| 품질 | 백엔드·프론트·운영 테스트가 통과해야 Docker 이미지 빌드가 진행된다. |

## 3. 사용자·역할

모든 사용자는 동일한 메인 화면을 본다. 역할에 따라 버튼 동작만 다르며, 역할 승급·강등 화면은 만들지 않는다. 서비스 키와 외부 API 키 원문은 어떤 화면에도 표시하지 않는다.

| 역할 | 가능한 일 | 제한 |
| --- | --- | --- |
| 손님(GUEST) | 지도·사이드바 검색, AI 채팅, 결과 조회 | 운영 대시보드 버튼을 누르면 화면 블러와 `관리자 전용 화면입니다.` 팝업을 표시한다. |
| 하급 관리자(JUNIOR_ADMIN) | 손님 기능, 운영 대시보드 조회, 요청 재처리·캐시 갱신 | 테스트 전용 장애 주입·보고서 내보내기 등 상급 전용 기능은 사용할 수 없다. |
| 상급 관리자(SENIOR_ADMIN) | 하급 관리자 기능, 시연 모드 Test API 제어, 필요한 운영 보고서 내보내기 | 역할 자체를 변경하거나 키 원문을 조회할 수 없다. |

## 4. 핵심 사용자 흐름

### 4.1 첫 진입·지도 검색

1. 첫 진입 시 **강남역 주변, 표시 범위 1 km(실제 반경 0.5 km), 급속·완속**으로 기본 검색한다.
2. 사이드바의 `검색 중심` 입력칸은 비어 있는 상태로 시작한다.
3. 사용자가 장소명을 입력하면 카카오 장소 검색 결과를 연관 후보로 표시한다.
4. 사용자가 후보 하나를 선택하면 장소 좌표를 검색 중심으로 확정하고 충전소 검색을 실행한다.
5. 지도 마커 hover에는 `상호명 · 현재 빈자리/총 충전기 수`를, click에는 상태·출처·보고 시각·상세 정보를 표시한다.

### 4.2 자연어 채팅 검색

1. 입력 가드레일이 위험한 요청을 먼저 차단한다.
2. `사당역`, `서울역 2km 급속`처럼 명확한 입력은 규칙 기반 Planner가 즉시 SearchRequest 초안을 만든다.
3. `그 조건에서 급속만`, `두 키로 정도로 바꿔줘`처럼 직전 검색 문맥 또는 자연어 수량 해석이 필요한 입력만 GPT-4o mini를 사용한다.
4. `서울`, `강남`처럼 넓거나 모호한 장소는 카카오 상위 2개 후보와 1순위 제안을 보여 준다. 예: `서울특별시청 주변으로 찾을까요?`
5. 사용자가 후보·조건을 확인한 뒤에만 충전기 상태 조회를 시작한다.
6. `10 km`처럼 표시 범위 1·2·3 km 밖의 요청은 검색하지 않고 가능한 범위를 안내한다.

### 4.3 검색 조건

| 조건 | 규칙 |
| --- | --- |
| 지역 | 서울 주소의 카카오 장소 후보만 선택한다. 서울 밖 후보·충전소는 제외한다. |
| 충전기 타입 | 급속, 완속, 급속·완속 전체 |
| 표시 검색 범위 | 1 km, 2 km, 3 km |
| 실제 반경 | 표시 범위의 절반인 0.5 km, 1.0 km, 1.5 km |
| 기본값 | 표시 범위 1 km, 급속·완속 전체 |

## 5. 기능 요구사항

### 5.1 검색·지도

| ID | 요구사항 |
| --- | --- |
| FR-01 | 카카오 장소 API로 입력 장소의 서울 내 후보를 검색하고, 지도 JavaScript SDK로 지도·마커를 표시한다. |
| FR-02 | 카카오 결과는 장소 후보·지도 용도에만 사용한다. 충전 가능 상태의 근거로 사용하지 않는다. |
| FR-03 | 환경공단 API로 충전기 상태와 보고 시각을 조회·정규화한다. |
| FR-04 | 사이드바 직접 입력은 Planner를 거치지 않고 동일한 SearchRequest로 Executor에 합류한다. |
| FR-05 | 채팅 검색은 장소·조건 확인 전에는 환경공단 충전기 조회를 실행하지 않는다. 단, 첫 진입 기본 검색은 예외다. |

### 5.2 결과 품질

| ID | 요구사항 |
| --- | --- |
| FR-06 | 결과에는 충전소명, 충전기 타입, 상태, 출처, 최종 보고 시각, 거리, 품질 판정을 표시한다. |
| FR-07 | 마지막 보고 시각이 7일을 넘었거나 없으면 `정보 지연` 또는 `확인 불가`로 표시한다. |
| FR-08 | 현재 빈자리 수가 음수이거나 총 충전기 수보다 크면 수치를 숨기고 안전한 상태로 처리한다. |
| FR-09 | 결과 없음, 요청 제한(429), 인증 만료, 외부 API 지연, LLM 처리 실패는 원인을 노출 가능한 안내 문구로 표시한다. |

### 5.3 멀티 에이전트·가드레일

| ID | 요구사항 |
| --- | --- |
| FR-10 | Planner, Executor, Critic, Memory Keeper는 역할과 권한이 겹치지 않게 동작한다. |
| FR-11 | 모든 처리 단계는 `request_id`로 연결하고, SearchRequest·출처·갱신 시각·재시도·Critic 판정을 Handoff에 남긴다. |
| FR-12 | 지침 무시, 환경변수·API 키 요구, 타인 대화·정보 요구, 권한 변경 요구는 Planner와 외부 API 호출 전에 차단한다. 차단 원문은 저장하지 않는다. |
| FR-13 | 확인되지 않은 충전 상태를 `충전 가능`으로 단정하지 않는다. |

### 5.4 운영 대시보드

| ID | 요구사항 |
| --- | --- |
| FR-14 | 운영 개요, 에이전트 처리, 가드레일, 안정성·힐링, 배포 파이프라인, 컴플라이언스 메뉴를 제공한다. |
| FR-15 | 요청 성공·실패·재시도, 품질 판정, 가드레일 차단 수, 외부 API·컨테이너·Auto Healing 상태를 현재 기록 기준으로 표시한다. |
| FR-16 | 운영자는 실패 요청을 최대 2회 수동 재처리하고, 캐시 갱신을 요청할 수 있다. |
| FR-17 | Test API와 `/boom/1`~`/boom/5` 시연 기능은 테스트·시연 모드에서만 사용한다. |

## 6. 데이터 출처 정책

| 데이터 | 출처 | 사용 목적 | 제한 |
| --- | --- | --- |
| 장소 후보·좌표·지도 | 카카오 장소 API, JavaScript SDK | 장소명 해석, 지도·마커 | 실시간 충전 상태 근거로 사용 금지 |
| 충전기 상태·보고 시각 | 환경공단(KECO) API | 충전 상태, 타입, 최종 보고 시각 | 지연·이상값은 Critic이 안전하게 처리 |
| 자연어 구조화 | OpenAI GPT-4o mini | 문맥형 조건·자연어 수량 해석 | 장소 검색·외부 API 호출 권한 없음 |

## 7. 비기능 요구사항

| 영역 | 기준 |
| --- | --- |
| 응답 속도 | 명확한 장소·수치 입력은 규칙 기반 빠른 경로를 우선한다. LLM은 필요한 문맥형 요청에만 사용한다. |
| 장애 격리 | 외부 API의 일시 오류만 자동 재시도하고, 인증·형식 오류는 재시도하지 않는다. |
| 재시도 | 자동 재시도는 최대 2회이며, 수동 재처리 한도와 별도로 기록한다. |
| 메모리 | 이번 버전은 DB·Redis 없이 백엔드 프로세스 메모리를 사용한다. 컨테이너 재기동 시 대화·운영 이력은 초기화된다. |
| 키 관리 | `.env`로 주입하며, 브라우저에는 지도용 JavaScript 키만 전달한다. |
| 테스트 | 단위·계약·복구 테스트는 Docker 없이 `pytest`로 실행한다. |
| 통합 검증 | 실제 화면·컨테이너·배포 흐름 검증 시에만 `docker compose up --build`를 사용한다. |

## 8. 테스트·배포 요구사항

### 8.1 테스트 범위

| 대상 | 현재 검증 항목 |
| --- | --- |
| 백엔드 | Planner 빠른 경로·LLM 경로, SearchRequest, 가드레일, 서울 범위, Critic, 재시도, Handoff, Test API |
| 프론트 | 채팅 안내, 지도 HTML 안전성, 역할별 화면 규칙, 운영 대시보드 데이터 계약 |
| 운영 | Watchdog 재시작 정책, 재시작 제한·쿨다운, Docker 배포 실패·롤백 정책 |
| 장애 시나리오 | normal, stale, invalid_count, timeout(FT-01), executor_exception(FT-02), llm_invalid_schema(FT-04) |

### 8.2 배포 흐름

`pytest` 통과 → Docker Compose 구성 검증·이미지 빌드 → GHCR 이미지 게시(main) → AWS EC2 Docker Compose 배포·healthcheck → 실패 시 기존 이미지 롤백

GitHub Actions의 앞 단계가 실패하면 이후 빌드·게시·배포 단계는 실행하지 않는다. AWS 배포는 Docker Compose 기반이며 Kubernetes·매니페스트는 이번 범위에 포함하지 않는다.

## 9. 범위 제외

- Kubernetes Pod·Service·매니페스트 운영
- PostgreSQL·Redis 등 영속 DB와 DB 장애 시나리오
- 일반 주차장 탐색, 실시간 주차 빈자리, 빈자리 예측
- 충전 요금·주차 요금·외부인 이용 가능 여부의 확정 표시
- 사용자 역할 승급·강등 관리 화면
- 실제 API 키·세션 토큰·개인정보의 화면 표시 또는 로그 저장

## 10. 승인 체크리스트

- [ ] 지도·사이드바와 자연어 채팅이 같은 SearchRequest 계약으로 동작한다.
- [ ] 카카오와 환경공단의 역할이 분리되고 출처·보고 시각이 결과에 표시된다.
- [ ] 입력·행동·출력 가드레일과 Handoff 이력이 구현된다.
- [ ] 자동 재시도 최대 2회와 안전한 오류 응답이 동작한다.
- [ ] 백엔드·프론트·운영 pytest가 통과한다.
- [ ] Docker Compose 통합 실행과 GitHub Actions 배포 게이트를 확인한다.
