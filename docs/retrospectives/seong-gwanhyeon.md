## 맡은 역할

저는 ChargePin의 프론트엔드와 운영 대시보드 구성을 맡았습니다. 지도 마커에 충전 가능 대수를 보여 주고, 운영 개요·배포 파이프라인·컴플라이언스 메뉴를 권한별로 구성했습니다.
발표 자료, 대본, 예상 질문, README 정리도 맡았고 백엔드가 부족한 부분은 옆에서 보완했습니다.

## 어려웠던 점

가장 어려웠던 것은 환경공단 데이터의 갱신 시각이 1~15분 전부터 72시간 이상까지 제각각이라, 믿을 수 없는 숫자를 단정하지 않는 기준을 화면에서 지키는 일이었습니다.
막판에 PRD와 설계서가 새로 나와 자료를 다시 맞춰야 했고, 결국 필수 장애시험은 시간 안에 실행하지 못했습니다.

## 해결 과정

신뢰할 수 없는 숫자는 숨기고 "정보 지연", "갱신 시각 확인 불가", 회색 번개 마커처럼 이유를 화면에 표시했습니다. 대시보드 값 옆에는 기준 출처를 적고 없는 수치는 만들지 않았습니다.
시간이 부족한 부분은 장애시험을 발표에서 빼고 “8.48초 1회 실측”으로 한계를 밝혔으며, 실패 알림은 Discord 웹훅으로 가볍게 먼저 연결했습니다.

## 배운 점

데이터의 한계를 숨기지 않고 드러내는 것이 서비스 신뢰를 만들고, 막는 장치(가드레일)와 막았다는 증명(컴플라이언스)은 서로 다른 역할이라는 것을 배웠습니다.
증빙이 없는 것은 "했다"고 말하지 않고 미착수로 남기는 태도가 오히려 힘이 되었고, 다음에는 시험 계획과 증빙을 일정 초반부터 챙기겠습니다.
