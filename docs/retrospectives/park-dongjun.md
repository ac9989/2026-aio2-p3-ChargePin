맡은 역할
팀장·PM 및 Backend 영역에서 ChargePin의 PRD·멀티 에이전트 아키텍처를 설계하고, Planner 자연어 처리·보안 가드레일·Handoff·운영 로그 구조를 구현·통합했다. 또한 팀 작업을 main 브랜치에 병합하고 산출물 문서를 최신 구현 기준으로 관리했다.

어려웠던 점
장소명, 검색 반경, 충전기 타입이 섞인 자연어에서 규칙만으로는 문맥을 이어가기 어려웠고, LLM을 항상 호출하면 응답 속도와 판단 일관성이 떨어지는 문제가 있었다. 팀원별 브랜치의 기능과 테스트·배포 결과를 하나의 코드와 문서 기준으로 맞추는 과정도 복잡했다.

해결 과정
명확한 장소·조건은 규칙 기반 빠른 경로로 처리하고, 직전 조건을 바꾸는 문맥형 요청만 LLM이 처리하도록 Planner를 분리했다. 카카오 장소 후보를 통해 서울 범위를 확인하고, Executor·Critic·Memory Keeper의 역할과 재시도 이력을 request_id로 연결했다. 또한 입력 가드레일, 구조화 로그, CI 실패 Discord 알림을 추가해 오류와 운영 이력을 확인할 수 있게 했다.

배운 점
멀티 에이전트 서비스에서는 LLM 자체보다 역할 경계, 재시도 기준, 검증 흐름, 기록 구조를 명확히 설계하는 것이 중요하다는 점을 배웠다. 팀장으로서 기능 구현뿐 아니라 브랜치 병합, 테스트 증빙, 문서 일치 여부까지 함께 관리해야 서비스가 완성된다는 점을 경험했다.
