# ChargePin 프론트엔드

화면 설계서와 아키텍처 초안을 기준으로 만든 프론트엔드 미리보기입니다.
현재 장소·상태·운영 수치와 대화 결과는 모두 예시입니다.

## 준비

- Python 3.11 이상
- 프로젝트에 필요한 패키지: 이 폴더의 requirements.txt
- 실제 지도 사용 시 카카오 지도 JavaScript 키와 등록된 실행 도메인

예시 실행 환경: Python 3.12.14, Streamlit 1.66.1.

## 실행

PowerShell에서 이 폴더로 이동한 뒤 아래 명령을 사용합니다.

    python -m pip install -r requirements.txt
    python -m streamlit run app.py

처음에는 접속 코드를 입력합니다. 기본 시연 코드는 일반 사용자 `AIO2BOOT`, 관리자 `AIO2`이며
대소문자를 구분하지 않습니다. 관리자는 사용자 화면과 대시보드를 오갈 수 있고, 일반 사용자는
사용자 화면만 이용합니다. 접속 종료 후 다른 코드로 다시 입장할 수 있습니다.

별도 터미널에서 다음처럼 실행해도 같은 접속 흐름을 사용할 수 있습니다.

    cd dashboard
    python -m streamlit run app.py --server.port 8502

이 접속 방식은 두 공유 코드로 Streamlit 세션에서 화면 접근을 구분하는 시연용입니다.
개별 계정, 안전한 인증 및 백엔드 권한 검사를 대체하지 않으므로 실제 배포에 사용하면 안 됩니다.
시연 코드는 `CHARGEPIN_USER_CODE`와 `CHARGEPIN_ADMIN_CODE` 환경 변수로 바꿀 수 있고,
두 값은 서로 달라야 합니다. 백엔드와 실제 계정 인증은 아직 연결되지 않았습니다.

## 지도

기본 상태에서는 실제 위치를 나타내지 않는 예시 그림을 보여 줍니다.
카카오 지도 JavaScript 키를 발급받고 사용하는 도메인을 카카오 개발자 설정에 등록한 뒤,
현재 PowerShell 세션에서 다음 환경 변수를 설정하면 지도 SDK를 불러옵니다.

    $env:EV_KAKAO_JS_KEY = "발급받은 JavaScript 키"

서버용 REST API 키나 다른 비밀키를 여기에 넣지 않습니다.
JavaScript 키는 웹 지도에 사용되므로 브라우저에서 확인될 수 있습니다.
키와 도메인 설정은 카카오 공식 안내를 따릅니다.

## 백엔드 연동 전 확인 사항

- 검색은 충전 장소를 대상으로 하며, 결과에는 장소 유형(주차장·아파트·전용 충전소),
  충전요금과 별개의 주차 요금, 일반 이용 가능 여부 또는 이용 제한을 구분합니다.
- 장소 유형·주차 요금·이용 조건이 없거나 확인되지 않으면 `확인 필요`로 표시합니다.
  각 항목의 실제 API 제공 여부, 출처·갱신 시각과 제한 사유는 백엔드와 확인해야 합니다.
- services/preview.py의 SearchCriteria과 PreviewProvider은 프론트 내부의 임시 표현입니다.
  실제 요청·응답 형식은 백엔드 담당자와 합의한 뒤 연결 부분에서 조정합니다.
- 대화는 실제 LLM이 아니라 제한된 규칙을 이용한 시연입니다. 서울·서울역·강남 등 일부 예시
  지명을 대표 위치로 검색하고 이를 대화에 명시합니다. 실제 장소 검색은 아직 연동되지 않았습니다.
- 추가 조건은 장소 유형, 주차 요금, 외부인 이용 가능 여부, 주차 현황과 충전기 이용 제한시간입니다.
  외부인 이용은 명시된 조건에 따라 가능·불가능·주의로 표시하며 아파트라는 이유만으로 판단하지 않습니다.
  필터에 필요한 정보가 확인되지 않으면 해당 조건을 만족하는 결과로 포함하지 않습니다.
- 이용 제한시간은 충전기 사용 허용 시간이며 완충 예상 시간이 아닙니다. 주차 현황은 충전기
  사용 상태와 별도입니다. 실제 데이터 제공 여부와 출처·갱신 시각은 백엔드와 확인해야 합니다.
- 3시간 뒤 자리 가능성은 시연을 위한 가상 값입니다. 실제 예측 모델이나 근거 자료는 아직 없으며
  실제 예측인 것처럼 표시하지 않습니다.
- 예시 지도의 시설과 관리자 지표는 실제 데이터를 나타내지 않습니다.
- 운영 대시보드는 관리자 한 명이 모든 운영 정보를 보는 화면 예시입니다.
  현재 Streamlit에서 시연 코드별 화면 접근을 구분하지만, 실제 계정 로그인, 백엔드
  권한 검사, 감사 기록과 서버 작업은 아직 구현되지 않았습니다.
- 정확한 서울 행정 경계, 위치 변환, 인증, 예외 응답과 관리자 API는
  서버 계약 및 실제 연동 후 함께 검증해야 합니다.
- 카카오 지도는 키가 없으면 예시 그림으로 표시됩니다.
  실제 키와 등록 도메인을 이용한 연결 확인은 아직 필요합니다.

## 운영 대시보드와 배포 이력

- 메뉴는 운영 개요, 서비스 운영, 배포 · 감사 이력으로 묶었습니다.
  예시 역할 선택과 별도의 정책 · 권한 관리 화면은 두지 않습니다.
- 배포 화면에서 예시 실행과 단계를 선택하면 결과와 해당 예시 로그를 볼 수 있습니다.
  감사 이력은 운영 이벤트와 별도로 표시하며 작업 유형과 페이지를 선택할 수 있습니다.
- 현재 실행·단계·로그·감사 기록은 `dashboard/preview_data.py`의 예시이며
  GitHub Actions, 배포 서버 및 실제 감사 저장소에 연결되어 있지 않습니다.
- 실제 연동 시 백엔드가 저장소 권한을 확인하고 실행 목록, 각 작업과 단계의 상태,
  시작·종료 시각, 결과, 로그 또는 원본 링크를 제공하도록 팀에서 계약을 정합니다.
  실제 작업 순서와 단계는 워크플로우에 따라 다를 수 있습니다.
- GitHub 인증 정보는 서버에서 관리하고 화면에 넣지 않습니다. 로그 접근 권한,
  민감정보 처리, 보관 기간과 만료된 로그 표시는 실제 운영 환경에 맞춰 정해야 합니다.
- GitHub 공식 문서: [실행 이력과 로그](https://docs.github.com/en/rest/actions/workflow-runs),
  [작업 및 단계 정보](https://docs.github.com/en/rest/actions/workflow-jobs)
